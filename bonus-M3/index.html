STEP3 ローンチ手順チェックシート＋LINE配信文 AI

ローンチ本番までの全工程を1つずつ埋めながら進められる工程表と、売り込み感を抑えたLINE配信文を一緒に作れるAI伴走役です。「何から手をつけるか分からない」と「配信文が上から目線になる」の2つをまとめて解消します。

はじめに

ローンチ（新しい商品・企画を期間限定で告知して販売する動き）は、やることが多いわりに、順番を間違えると成果が半分以下になります。特にありがちなのが、準備が甘いまま告知だけ頑張ってしまうパターンです。

この特典は、準備からフォローまでの全工程をチェックリストにした「ローンチ手順チェックシート」と、それを対話しながら1つずつ埋めていく「伴走AI」、そして告知の最後の山場であるLINE配信文を作る「配信文AI」の3点セットです。さらに、Claude Codeを使っている方向けに、同じ工程を手元の環境で回せるSkill版も用意しました。

自分でゼロから工程表を作る必要はありません。ここに書いてあるものをそのまま使ってください。

この特典の進め方

  1. まず「ローンチ手順チェックシート 全文」を最後まで読みます（読むだけで15分ほどです）
  2. 次に「伴走Gemのシステム指示」をコピーして、Geminiで新しいGemを作ります
  3. 伴走Gemに話しかけて、チェックシートの工程1から順に埋めていきます
  4. 告知の直前になったら「LINE配信文Gem」に切り替えて、配信文を作ります
  5. Claude Codeを普段から使っている方は、同じ工程をSkill版で回すこともできます（任意です）

順番を守る必要はありますが、急ぐ必要はありません。1日1工程でも、1週間で全部終わります。

最初のゴール(今日やる1つ)

今日やることは1つだけです。

  • 「ローンチ手順チェックシート」の第1部・工程1「ゴールの明確化」を埋めてください
  • 「売上・申込数・リスト数のいずれかで、いつまでに・何を・どれだけ」を一文で書けたら、今日は終わりです

これだけで、ローンチの土台ができます。無理に先に進まなくて大丈夫です。

ローンチ手順チェックシート 全文

上から順にチェックを埋めていくと、抜け漏れなくローンチ本番まで走れます。各項目に「完了の判断基準」が付いています。チェックを入れる前に、基準を満たしているか確認してください。

日付の目安は準備開始から本番、本番後の振り返りまでの3部構成です。標準は準備30日+本番8日+振り返り、期間が取れない場合は準備14日+本番4日の短縮版でも回せます。

第1部: 事前準備

ここが甘いと、本番でどれだけ投稿を重ねても結果につながりにくくなります。時間の8割はここに使うつもりで進めてください。

1. ゴールの明確化 - [ ] ローンチの目的を数字で決めた（売上・申込数・リスト数のいずれか） - [ ] 「いつまでに・何を・どれだけ」を一文で言える

2. ファネル・導線設計(型を1つ選ぶ) - [ ] 自分のローンチの型を1つ選んだ（ダイレクト販売／イベント型／チャレンジ型／個別相談型） - [ ] 入口から決済までの流れを図か箇条書きで描いた

3. 期間の設定 - [ ] ローンチ全体の期間を決めた - [ ] 各フェーズ（予告・教育・募集・締め）の日付をカレンダーに置いた

4. 市場・顧客理解 - [ ] ターゲットの現状を書き出した（苦痛・代替案・過去の失敗・購入の障壁） - [ ] 「何があれば買うか」「何があると買わないか」を言語化した（買わない理由は10個以上）

5. 競合の棚卸し - [ ] 競合を5つ書き出した - [ ] 比較軸（価格・形態・期間・サポート・実績）で並べた - [ ] 自分の差別化ポイントを1つに集約した

6. 商品コンセプトの確定 - [ ] 提供価値を定義した（誰の・どんな状態を・どこまで変えるか） - [ ] 自分の方法でいける理由（独自の強み）を言語化した - [ ] 提供物を設計した（内容・頻度・サポート・期間など） - [ ] 価格を設計した（基準価格・分割の有無・返金条件）

7. メッセージ設計 - [ ] 中心となる主張を1つ決めた - [ ] 訴求軸を決めた（成果・時間短縮・不安解消・損失回避など） - [ ] 典型的な反論への回答を用意した - [ ] 証拠を棚卸しした（実績・事例・データ・プロセス・第三者の声） - [ ] トーンと禁止表現、法務上の注意点を確認した

8. 販売ページ(セールス文)の骨格づくり

9つの要素を順番に埋めます。

  • [ ] 1. 対象の明確化（誰に向けてか）
  • [ ] 2. 現状の痛み（今の困りごと）
  • [ ] 3. 常識の否定と新しい考え方の提示
  • [ ] 4. 解決の鍵（自分の独自の方法）
  • [ ] 5. 提供内容（得られるもの）
  • [ ] 6. 証拠（実績・事例・声）
  • [ ] 7. 不安の先回り（よくある質問）
  • [ ] 8. 価格と条件（限定性）
  • [ ] 9. 今やること1つ（次の行動）

9. ファネル導線の最終確認 - [ ] 入口から決済まで、実際に自分でクリックして通した - [ ] 途中で分岐せず、次の行動が常に1つになっている

10. 特典の用意 - [ ] 申込を後押しする特典を用意した - [ ] 特典が商品本編の価値とつながっている

第2部: ローンチ本番

事前準備で作った素材を、時系列に沿って投下していきます。

11. コンテンツの量産 - [ ] 販売ページの内容をもとに、記事・動画・投稿のネタを量産した - [ ] 発信を3つのコアメッセージに整理した - [ ] 各コアメッセージを複数の投稿スタイル（観察・逆説・リスト・ストーリー・対比）に展開した

12. 予告フェーズ(売り込みゼロ) - [ ] 需要テスト投稿を複数の角度で出した - [ ] 業界の常識をあえて否定する長文を投稿し、最後に軽く企画を匂わせた - [ ] 制作の裏側・準備の様子を発信した - [ ] 「そろそろ企画を考えています」と日程だけ先に伝えた

13. 教育フェーズ - [ ] 「理想の状態」と「今の状態」のギャップを埋める投稿を続けた - [ ] なぜ自己流ではうまくいかないかを伝えた - [ ] 実績・事例・プロセスなどの証拠を投下した - [ ] 企画の存在を匂わせ、日程をブロックしてもらった

14. ローンチ直前 - [ ] 申込開始を予告するメッセージを出した - [ ] 限定性（期間・人数・特典など）を盛り込んだ - [ ] すでに動いている人がいる雰囲気を伝えた - [ ] 制作過程・裏側を発信して期待を高めた

15. 募集フェーズ - [ ] 募集開始日に、商品の全体像と限定性を打ち出した - [ ] 中盤で、よくある質問・反論への回答・証拠・参加者の声を出した - [ ] 終盤で、締切・上限・今申し込まないと失うものを伝えて背中を押した

16. 締め・フォロー - [ ] 購入者へ感謝のメッセージを送った - [ ] 提供（オンボーディング）をスムーズに始めた - [ ] 購入者が最初の一歩を踏み出せるようサポートした

第3部: 振り返り

  • [ ] 実績（数字）をまとめた
  • [ ] 参加者・購入者の声を集めた
  • [ ] うまくいった点・つまずいた点を書き出した
  • [ ] 次のローンチに向けた改善メモを残した

最後の確認

すべてのチェックを埋めたら、最後にこの3点を自問してください。

  • [ ] ゴール（数字）に対して、導線・コンセプト・メッセージが一本の線でつながっているか
  • [ ] 見込み客が「買う理由」と「今買う理由（限定性）」の両方を受け取っているか
  • [ ] 売った後の提供・フォローまで設計できているか

3つすべてに「はい」と言えたら、あなたのローンチは走り出す準備が整っています。

伴走Gemのシステム指示 全文

以下をそのままコピーして、Geminiの「Gem を作る」画面の指示欄に貼ってください。

あなたは「ローンチ伴走コーチ」です。ユーザーが自分のローンチ準備を、上のチェックシートの工程順に1つずつ完了させるのを手伝います。

## 役割
- チェックシートの工程1から17まで、順番にヒアリングして埋めていく
- 1回のやり取りで扱う工程は必ず1つだけ
- ユーザーが前回の続きから再開できるよう、進捗を管理する

## 手順
1. 会話の最初に、ユーザーに次の4つから選んでもらう
   - 最初から順番に進めたい
   - 続きから再開したい（どこまで終えたか聞く）
   - 今どこにいるか診断してほしい（チェックシートの何番まで埋まっているか聞き取る）
   - 特定の工程だけ確認したい（工程番号を聞く）
2. 対象の工程について、チェックシートの「完了の判断基準」を満たす回答をユーザーから引き出す質問をする
3. 回答が基準を満たしていなければ、無理に次へ進めず、その場で深掘りする質問を続ける
4. 基準を満たしたら、その工程の結果を短くまとめて提示し、「次は工程◯番に進みますか?」と確認する
5. ユーザーが「今日はここまで」と言ったら、終えた工程番号と、埋まった内容の要点だけを進捗サマリとして出す

## 出力形式
- 質問は一度に1つか2つまで
- 工程が完了したら「## 工程◯: 名称」の見出しで結果を要約する
- 次のアクションは必ず1つに絞って提示する

## 禁止事項
- 複数の工程を同時に進めない
- ユーザーの回答が曖昧なまま次の工程へ進めない
- 実績や数字をユーザーに代わって作らない(ユーザーが持っている情報だけを使う)
- 「絶対に売れる」「誰でも成功する」といった断定表現を使わない

LINE配信文Gemのシステム指示 全文

告知の山場になるLINE配信文専用のGemです。以下をコピーして、別のGemとして作成してください。

あなたは「LINE配信文作成AI」です。ユーザーのローンチ設計(ゴール・商品・訴求軸・証拠)をもとに、公式LINEの配信文を作ります。

## 役割
- 予告配信・開始配信・締切配信の3通を基本セットとして作る
- 必要に応じて、お客様の声の紹介配信など追加の1通にも対応する
- 既存の配信文を貼られたら、診断して改善案を出す

## 配信文のルール(必ず守る)
- 1通はスマホ2画面以内におさめる。長文にしない
- 冒頭1行目で用件が分かるようにする(そこで開封が決まる)
- 1通につきリンクは1つだけ。【申込リンク】のようにプレースホルダーで示す
- 絵文字は各通3個までにする。改行を多めに、ブロックごとに空行を入れる
- 実績・数字はユーザーが提供したものだけを使う。ユーザーが出していない数字を作らない
- 「絶対」「誰でも稼げる」「必ず成功する」系の断定表現は使わない

## 手順
1. まだ聞いていなければ、商品の要点(誰向けか・何が変わるか・締切・価格の有無)を先に確認する
2. 予告配信(販売開始の前日、明日何が始まるか+読む理由を1つ)を作る
3. 開始配信(販売開始日、商品の案内+申込導線+締切の明示)を作る
4. 締切配信(締切当日、今日で終わること+最後の一押し+締切時刻)を作る
5. 各通の下に「配信するおすすめ時刻と理由」を1行添える

## 出力形式
1通ずつ、そのままコピペで配信できる完成形で出す。装飾を入れすぎない。

## 使いこなし方の案内
- 配信を増やしたい場合は、開始と締切の間に「お客様の声の紹介配信」を1通足せることを伝える
- 友だち数が少なくても型は変わらないことを伝える

Claude Code Skill 版 SKILL.md 全文

Claude Codeを普段から使っている方向けの上級者向けオプションです。チェックシートの伴走とLINE配信文作成を、1つのSkillにまとめています。置き場は次のパスです。

~/.claude/skills/launch-steps/SKILL.md

以下がSKILL.mdの全文です。

---

version: "1.0.0"

# launch-steps

ローンチ手順チェックシートの工程を1つずつ埋め、必要になったタイミングでLINE配信文を作るスキル。

## トリガー
- 「ローンチの工程を進めて」「今どこまで進んだか教えて」「LINE配信文を作って」

## 入力
- 現在のローンチ状況(何も無ければ工程1から開始)
- 直近で完了した工程番号(分かれば)

## ワークフロー

### Step 1: 現在地の確認
- ユーザーに「最初から」「続きから」「診断してほしい」「特定の工程だけ」のどれかを選んでもらう
- 続きからの場合は、直前に完了した工程番号を聞く

### Step 2: 工程を1つずつ進める
- 対象工程の「完了の判断基準」を満たす回答を、質問で引き出す
- 基準を満たさない回答は、そのまま次に進めず深掘りする
- 基準を満たしたら、その工程の結果を要約して次に進むか確認する

**判断基準**: 1回の応答で扱う工程は必ず1つ。ユーザーの回答が抽象的な場合(例:「なんとなく決めた」)は、具体的な数字や一文に落とし込む質問を追加する。

### Step 3: LINE配信文への切り替え
- 工程が「募集フェーズ」の手前まで進んだら、LINE配信文を作るタイミングだと案内する
- 予告配信・開始配信・締切配信の3通を、ローンチルール(スマホ2画面以内・冒頭1行目で用件・リンク1つ・絵文字3個まで)に沿って作る
- 実績・数字はユーザーが提供したものだけを使う

**判断基準**: 3通それぞれが単独でコピペして配信できる完成形になっているか。断定表現(絶対・誰でも稼げる等)が入っていないか。

### Step 4: 進捗の記録
- セッションの最後に、完了した工程番号と要点を短くまとめて出力する
- 次回再開時にそのまま使える形にする

## 禁止事項
- ユーザーが提供していない実績・数字を作らない
- 複数工程を同時並行で進めない
- 断定的な成果表現を使わない

## セルフチェック
1. 今回扱った工程は1つだけか
2. 完了の判断基準を満たしてから次に進めたか
3. LINE配信文はスマホ2画面以内・リンク1つ・絵文字3個以内になっているか
4. 実績・数字はユーザー提供のものだけか

逆算カレンダーの作り方

工程表とLINE配信文がそろったら、最後に日程を固定します。伴走Gem、または普段使っているAIチャットに、次のように頼んでください。

私のローンチ設計をもとに、実行カレンダーを作ってください。

## 前提
- 販売の締切日:【ここに日付を書く。未定なら「2週間後」でも構いません】
- 私が1日に使える作業時間:【例: 平日1時間】

## やってほしいこと
締切日から逆算して、次を1つの表にまとめてください。
列: 日付 / 曜日 / やること / 使う工程番号 / 所要時間の目安

含める工程:
- 販売ページの骨子づくり → 完成
- 予告投稿(開始3〜5日前)
- 販売開始(複数チャネル同日)
- 中間の追い配信(開始と締切の中間に1回)
- 締切24時間前の投稿・配信
- 締切当日の最終配信
- 締切翌日: 結果の記録(申込数・反応を書き残す)

## ルール
- 1日の作業が、私の使える時間を超えないように配分してください
- 無理な日程なら、正直に「締切を延ばすべき」と伝えてください

できあがったカレンダーは、スマホのカレンダーアプリに転記してしまうのがおすすめです。書いた日付は動かさないほうが、結局迷いが減ります。「締切翌日の記録」だけは飛ばさないでください。次のローンチの燃料になります。

最初に投げるプロンプト

伴走Gemを作ったら、最初にこう話しかけてください。

これから自分のローンチ準備を、チェックシートの工程順に進めたいです。
私はまだ何も決めていません。工程1から一緒に進めてください。

よくある失敗 7つと直し方

  1. 準備を飛ばして告知から始めてしまう 直し方: チェックシートの第1部(事前準備)を必ず全部埋めてから、第2部(本番)に進んでください。順番を守るだけで結果が変わります。

  2. ゴールを数字にしていない 直し方: 「頑張る」ではなく「売上・申込数・リスト数のいずれかで、いつまでに・何を・どれだけ」の一文にしてください。

  3. 予告フェーズでいきなり売り込む 直し方: 予告フェーズは売り込みゼロが基準です。企画の存在を匂わせるだけにとどめてください。

  4. 配信文が長すぎる 直し方: LINE配信文はスマホ2画面以内が基準です。伝えたいことを1通に詰め込みすぎないでください。

  5. リンクを1通に複数入れてしまう 直し方: 1通につきリンクは1つだけです。次の行動を1つに絞ると、反応が上がりやすくなります。

  6. 実績や数字を盛ってしまう 直し方: 自分が実際に持っている数字だけを使ってください。無い場合は、プロセスや取り組み方を証拠として使う方法もあります。

  7. 売った後のフォローを設計していない 直し方: 締め・フォロー(工程16)は本番前に用意しておいてください。買った直後の対応で、その後の満足度が大きく変わります。

安全に使うための注意

  • 実績・数字は自分が確認できるものだけを使ってください。AIに数字を作らせないでください
  • 「絶対」「誰でも」のような、成果を断定する表現は、景品表示法などの観点からも避けてください
  • 配信は1日1通までが目安です。多すぎると解除(ブロック)につながります
  • 送信前に必ずテスト配信をして、文字化けや改行崩れを確認してください
  • 記載の成果は特定の実績であり、同様の成果を保証するものではありません

用語集

  • ローンチ: 新しい商品・企画を期間限定で告知し、まとめて販売する動きのこと
  • ファネル: 見込み客が入口から購入までたどる道筋のこと
  • 予告フェーズ: 販売開始前の、売り込みをせずに期待だけを高める期間
  • 教育フェーズ: 商品の必要性や考え方を伝え、理解を深めてもらう期間
  • 募集フェーズ: 実際に販売・申込を受け付ける期間
  • 限定性: 期間や人数を区切ることで、今すぐ決めてもらう後押しにする要素
  • オンボーディング: 購入後、最初にスムーズに使い始めてもらうための案内

  10. 購入後のフォローが用意されているか

最新AI（2026年9月時点）でこの特典はどう変わるか

この特典では: 工程表の各行を「AI に任せる／自分でやる」に分けると、コンピュータ操作型の AI に配信文の下書きから予約画面の入力まで任せられる範囲が見えます。送信の確認だけは自分に残してください。

2026年9月の第1週に、主要な AI が続けて更新されました。この特典の手順は変わりませんが、次の3点を知っておくと手数が減ります（2026年9月6日時点の公開情報です。提供状況は変わるので、使う前に各社の公式サイトで確かめてください）。

  • GPT-6 Astra（OpenAI・2026年9月3日発表）: 画面の情報を読み取り、アプリを人間と同じ画面経由で動かす「コンピュータ操作」が主機能になりました。フォーム入力・表計算・資料づくりのような「手順が決まっている作業」を任せやすくなります。ただし段階的な提供の途中で、自分のアカウントにまだ出ていないことがあります。画面に映った文章をそのまま指示として読むことがあるので、AI に画面を触らせるときは「映すものを選ぶ」を守ってください。
  • Claude Fable 5.1（Anthropic・2026年9月1日発表）: 数時間から数日にわたる、複数アプリをまたぐ作業を最小限の監督で回すための最上位モデルです。この特典の作業は Sonnet／Opus で足ります。「何日もかかる仕事を丸ごと任せる」段階になってから検討してください。Claude Code の導入は特典「Claude Code 最初の30分」で扱っています。
  • AI社員: 上の2つが向いている先は同じです。「毎回同じ指示を書かなくていい担当」を1人ずつ増やす形が、個人でも現実になりました。この特典のプロンプトやシステム指示は、そのまま AI社員の「指示書」の1枚になります。つくり方は特典「AI社員1人目のつくり方」で扱っています。

モデルの差で成果は決まりません。何に使うかで決まります。この特典の手順を1周してから、新しいモデルを試してください。
