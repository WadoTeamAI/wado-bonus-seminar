X ポスト量産 OS わど版

この特典を使うと、あなたの発信テーマから「伸びる型」に沿った投稿ドラフトを、毎日迷わず6パターンまで作れるようになります。真っ白な画面で悩む時間が、型に沿って埋める作業に変わります。

はじめに

わどです。AIマネタイズの土台は「AI×SNS運用×コンテンツ販売」の3本柱だと考えています。具体的には、note やBrainでの記事づくり、Instagramのストーリーズ、そしてXの投稿。この特典はそのうちXの投稿を、毎日ゼロから考えずに回すための「型のOS」です。

Xは3本柱の中でいちばん頻度が高いぶん、いちばん息切れしやすいチャネルです。ネタを毎回一から考えると、1週間で止まります。だから「型」を先に持っておいて、そこにテーマを流し込むだけにします。

この特典で渡すのは3つです。

  1. 実際に効果が確認できている投稿の「型」の一覧（骨格・心理・字数の目安）
  2. その型に沿って自動でドラフトを作らせるための、Gemのシステム指示全文
  3. 同じ動きをClaude Codeで再現するためのSkill全文

読み終えたら、あなたのXアカウントに「型に沿って埋めるだけの運用」が立ち上がっている状態を目指します。

この特典の進め方

  1. 「1. 1日の回し方」で、投稿・リプ返信・振り返りのリズムを頭に入れる
  2. 「2. 型ごとの構成と例文」で、7系統30の型に目を通す。今週使えそうな型に印をつける
  3. 「3. Gemシステム指示」または「Claude Code Skill版」のどちらかをセットアップする（両方でも構いません）
  4. 「4. 運用シート」をコピーして、今週分の投稿予定を埋める
  5. 「最初に投げるプロンプト」でドラフトを1本作ってみる
  6. 「出す前の品質チェック」を通してから投稿する

最初のゴール（今日やる1つ）

今日はドラフトを1本作るところまでで十分です。「2. 型ごとの構成と例文」から、いちばんとっつきやすい「リスト保存型」を選び、「最初に投げるプロンプト」の文面に、あなたの発信テーマを1つ入れて実行してください。出てきたドラフトを保存すれば、今日のゴールは完了です。投稿は明日以降、時間割に沿って行えば十分です。

1. 1日の回し方（時間割）

投稿は「作る時間」と「返す時間」を分けます。どちらも同じくらい大事です。

時間帯 やること 狙い
朝（作業の合間） 前日の投稿の反応（保存・リプ・引用）をひと目確認 型ごとの手応えを記録する
日中の空き時間 翌日〜数日分の投稿ドラフトを型に沿ってまとめて作成 当日に慌てて考えない
15時〜23時のどこか1回 ドラフトを見直して投稿 この時間帯は反応が集まりやすい時間として知られています
投稿直後〜30分 来たリプライに全部返す 会話が始まった投稿ほど伸びやすいとされています
週末など 1週間分の型の配分（本数）を振り返る 同じ型に偏っていないかを見る

運用の原則は次の5つです。

  1. 役に立つ投稿と告知の比率はおおよそ4対1。告知は毎回ではなく、新しい情報が出たときの「初めての告知」だけを厚く扱う
  2. ノウハウ系の投稿は、しばらく期間を空ければ言い方を変えて再投稿できる。ただし人物の発言を引用した投稿は再投稿に向かない
  3. 反応が良かった投稿の直後は、プロフィールに来た人向けの固定投稿を、すぐ試せる系の内容に差し替える
  4. 投稿には基本的に画像か図解を添える。文字だけの投稿より反応が集まりやすいとされています
  5. 投稿後の30分はリプライ対応の時間として確保する。この初動が投稿全体の伸びに関わるとされています

2. 型ごとの構成と例文（全型・省略しない）

型を選ぶ前に知っておく5つのこと

Xでの評価のされ方には、次のような傾向があるとされています(公開されているアルゴリズム解説記事・一般に知られている運用知見)。

シグナル 傾向 使い方への反映
保存（ブックマーク） もっとも重視されるとされる行動 「あとで見返したい」と思わせる内容を作る
投稿者自身のリプライ返信 通常のいいねより大きく評価されるとされる 締めを問いかけにして、すぐ返信する
引用リポスト 通常より評価されやすいとされる 「これは自分のことだ」と思わせる書き出しにする
本文中のURL 表示されにくくなる傾向があるとされる リンクは本文でなくリプライ欄に置く
ハッシュタグの数 多いとスパムと判定されやすいとされる 0〜1個にとどめる

字数の目安は、型によって140字〜350字。1行に情報を詰め込みすぎず、1行=1情報で改行するのがコツです。

書き方の骨格 5型

まずは「どう書くか」の骨格を5つ持っておきます。ネタが変わってもこの骨格に流し込めば形になります。

型1 断定剥奪型 - 骨格: 1行目で世間の前提を否定する → 2〜4行目でなぜ間違いかを説明する → 箇条書きで正しいやり方を3〜5点挙げる → 締めで「これで何が変わるか」か次の一手を書く - 向いている場面: 「なんとなくこうだと思っていたこと」を覆したいとき - 例: 「AIに『いい感じにまとめて』と投げている人、実はかなり損しています。」

型2 数字実績開示型 - 骨格: 1行目で具体的な変化を数字で出す → 2行目で「やったことはシンプル」と続ける → 箇条書きでプロセスを3ステップ書く → 締めでリプライやプロフィールへ誘導する - 向いている場面: 自分や関わった人の変化を伝えたいとき（本人の許可を取ったうえで、匿名化して使う） - 例: 「作業時間が7日から2時間になりました。変えたのはツールではなく、順番です。」

型3 リスト保存型 - 骨格: 1行目で「◯選」「保存して」と明示する → 番号リストで5〜10項目を「見出し＋1行説明」で並べる → 締めで「保存して1つずつ試して」と促す - 向いている場面: ノウハウ・ツール・失敗例などをまとめて渡したいとき - 例: 「note1本をAIで書くまでの手順、全部見せます。」

型4 問い対話型 - 骨格: 1行目で「〇〇なあなたへ」と対象を絞る → 2〜3行目で状況を描写する → 転換の1行を入れる → 締めで二択の問いを投げる - 向いている場面: リプライでの会話を増やしたいとき。短めのほうがうまくいきます - 例: 「AIツールのブックマークが50個を超えている人へ。」

型5 速報解説型 - 骨格: 1行目で「発表が来た」という感情を先に出す → 2〜3行目で核心だけを書く → 箇条書きで影響を3点挙げる → 締めで「詳しくはリプライ欄で」と誘導する - 向いている場面: 新しいツールや機能が発表された直後 - 例: 「新しいアップデート、かなり来ました。」

切り口の一覧（実測ローテーション・7系統30型）

これは「何を出すか」の一覧です。わたし自身のアカウント運用を数か月分見直して、切り口ごとに反応の傾向を整理したものです。記載の成果は特定の実績であり、同様の成果を保証するものではありません。

A系統 リスト保存型（保存が集まりやすい系統） 1. 使ってよかったものランキング（時期ごとに更新する版） 2. 無料だけで組む環境まとめ 3. 用途特化ランキング（資料作成・リサーチなど、テーマを変えて回す） 4. ゼロから始める人向けのロードマップ 5. やりがちな失敗集（自分の過去の失敗として書く） 6. 工程をまるごと見せる（1つの作業をAIで進める全手順）

B系統 手順・指示文の配布（保存されやすい系統） 7. 保存推奨の一行型（短い文＋添付が主役） 8. 画像生成の裏技（指示文をそのまま見せる） 9. 型を横展開する指示文（1つの指示文を複数の用途に使い回す） 10. 用途別の指示文パターン集 11. コスト対比型（外注していた作業を自分でできるようになった話） 12. 手順を番号つきで公開するシリーズ型

C系統 権威の発言×時代の変化（頻度は少なめに使う系統） 13. 実在する発言の引用×歴史的な出来事との対比 14. 「特に◯個目が」型（続きが気になる書き方） 15. 公表された数字×時代の変わり目

D系統 数字での変化開示（信頼を積む系統） 16. 関わった人の変化のストーリー（本人許可・匿名化のうえで） 17. 自分の実績→プロセスを3行で（公開してよいか事前に確認したうえで） 18. 作業時間のBefore/After型 19. 失敗を開示してから構造を分析する型

E系統 断定を外す＋問いを添える（わどの型の応用） 20. 「実はかなり損してる」型 21. 「そもそも順番が違う」型 22. 対象を絞る書き出し型（引用リポストを誘発する） 23. 順番の指摘型（間違った順番と正しい順番を対比する）

F系統 問いかけで対話を生む系統 24. 二択型 25. あるある共感→転換型 26. 診断チェックリスト型

G系統 速報・解説系統 27. 新しい発表の第一報 28. 新機能とやり方をつなげる型 29. 翌日フォロー解説型（初心者向けにやさしく言い換える） 30. 無料期間や試せる期間の案内型（実在する期間のみ）

使い分けの結論

役に立つ内容(A・B・G系統)と、信頼を積む内容(D・E系統)を4対1くらいの比率で混ぜ、Cの権威引用は月に数回だけ、Fの問いかけ型で会話を作る。これが基本の配分です。最初は無理に30型を使い分けようとせず、A・B・E・Fの4系統だけで1週間回してみてください。

3. Gemシステム指示 全文 と Claude Code Skill版

同じ「型に沿ってドラフトを作る」動きを、Google GemでもClaude Codeでも動かせるようにしておきます。どちらか使いやすいほうで構いません。

Gemでの使い方

Gemini（Gemini アプリ）で「Gemを作る」を選び、名前を「X投稿量産OS」などにしたうえで、下のシステム指示をそのまま「指示」欄に貼り付けます。あとはチャットでテーマを渡すだけでドラフトが返ってきます。

システム指示（Gemに貼る）

あなたは「X投稿量産OS」というアシスタントです。ユーザーのXアカウント運用を、型に沿ったドラフト作りで支援します。

役割:
- ユーザーから発信テーマ・伝えたい主張・使いたい型（指定がなければおすすめを提案）を受け取る
- 型に沿って、投稿本文のドラフトを1〜3案作る

手順:
1. テーマと主張を確認する。曖昧な場合は1つだけ質問して確認する
2. 型が未指定なら、内容に合う型を1つ提案し理由を1行添える
3. 選んだ型の骨格に沿って本文を書く。1行=1情報で改行し、字数は140〜350字を目安にする
4. 締めに「保存」「リプライ」「二択の問い」のいずれかの行動を促す一言を入れる
5. 本文中にURLを入れない。URLが必要な場合は「リプライ欄に貼る」と案内する
6. ハッシュタグは付けない、または1個までにとどめる

出力形式:
- ドラフト本文
- 使った型の名前
- 投稿に添えるとよい画像・図解の案（1行）

禁止事項:
- 断定できない成果や数字を作らない。ユーザーが提示していない実績・数字を書き足さない
- 他人の発言を実在しないのに引用しない
- 「必ず」「絶対」など成果を保証する表現を使わない
- 政治・宗教・特定個人への批判につながる内容は書かない
- ユーザーが提示した情報以外を事実として断定しない

Claude Code Skill版

Claude Codeで同じ動きを再現する場合は、次の内容をそのままファイルにして使います。

---
name: x-post-mass-production-os
description: "発信テーマから、型に沿ったX投稿ドラフトを複数パターン作成するスキル。"
version: "1.0.0"
---

# X投稿量産OS

## トリガー
「Xの投稿を作って」「型に沿ってドラフトを出して」

## 入力
- テーマ・伝えたい主張（必須）
- 使いたい型（任意。未指定ならおすすめを提案する）

## ワークフロー

### Step 1: 型を選ぶ
テーマの性質に応じて、断定剥奪型／数字実績開示型／リスト保存型／問い対話型／速報解説型のいずれかを選ぶ。実績や具体的な数字が無い場合はリスト保存型か問い対話型を選ぶ。

### Step 2: 本文を書く
選んだ型の骨格に沿って本文を作成する。1行=1情報で改行し、字数は140〜350字を目安にする。締めに保存・リプライ・問いのいずれかを促す一言を添える。

### Step 3: 確認する
- 本文中にURLが入っていないか
- ハッシュタグが1個以内か
- 断定できない成果・数字を書いていないか
- 実在しない発言や実績を書いていないか

## 出力形式
- ドラフト本文
- 使った型の名前
- 添えるとよい画像・図解の案（1行）

## セルフチェック
1. 1行=1情報で改行されているか
2. 締めに行動を促す一言があるか
3. 事実として確認できない数字・成果を書いていないか

置き場は ~/.claude/skills/x-post-mass-production-os/SKILL.md です。フォルダごとコピーすれば、Claude Codeが自動で認識します。

5. 最新AI（2026年9月時点）で自動化できる所・できない所（取得日 2026-09-06）

2026年9月に発表された新しい大規模モデルは、パソコンの画面を直接見て操作できる機能が強化されています。投稿の下書き作成やスプレッドシートへの記録作業を、指示するだけで進められる場面が増えてきています。

一方で、公開されている情報の中には「画面の情報がそのまま指示として読み込まれる可能性がある」という注意点も示されています。AIに画面操作を任せる場合は、見せる画面を選ぶ必要があります。

この特典に当てはめると、次のように整理できます。

  • 自動化できる所: ドラフトの生成、運用シートへの記録の下書き、複数案の比較作成
  • 自動化できない・任せるべきでない所: 実際の投稿ボタンを押す最終判断、他人の発言の引用の事実確認、成果を保証するような表現になっていないかの最終チェック

AIに投稿の下書きを作らせる環境を整えたい場合は、別に用意している「Claude Code 最初の30分」で、最初の設定を先に済ませておくとスムーズです。

6. 次の一手

この特典は「稼ぎ方より、稼ぐ順番」で言うところのSTEP3(SNS・ローンチ)にあたる特典です。まだ最初の1件が決まっていない段階の方は、先にSTEP1・STEP2を進めることをおすすめします。

面談では、あなた専用の1枚(特注のロードマップ)を一緒に作ります。

最初に投げるプロンプト

あなたはX投稿の編集者です。以下の情報から、リスト保存型の投稿ドラフトを1本作ってください。

テーマ: [ここにあなたの発信テーマを書く]
伝えたい主張: [ここに一番伝えたいことを1文で書く]
条件:
- 番号リストで5〜7項目、各1行の説明つき
- 締めに「保存して1つずつ試して」に類する一言
- 本文にURLを入れない
- ハッシュタグは付けない

よくある失敗 7つと直し方

  1. 毎回ゼロから考えようとする → 型の一覧から選ぶことから始める
  2. 1投稿に情報を詰め込みすぎる → 1行=1情報で改行し、伝えることを1つに絞る
  3. 画像や図解を添えない → 添付ありの投稿を基本形にする
  4. 投稿してリプライを放置する → 投稿後30分はリプライ対応の時間として確保する
  5. 告知ばかりになる → 役に立つ内容と告知の比率を4対1くらいに保つ
  6. 本文にURLを入れてしまう → URLはリプライ欄に置く
  7. 同じ系統ばかり使ってしまう → 月次の系統配分シートで振り返る

安全に使うための注意

  • 実在しない発言や数字を、あるかのように書かない
  • 他人の実績や体験談を使う場合は、本人の許可を取り、特定できない形にする
  • 「必ず」「絶対」など成果を保証する言い方をしない
  • 政治・宗教・特定個人への批判につながる話題は避ける
  • 各SNSの利用規約は変わることがあるため、大きく方針を変える前に公式サイトで確認する

つまずいたときに聞くプロンプト

今週のX投稿がうまく回っていません。以下の状況から、原因と改善案を1つだけ教えてください。

今週投稿した本数: [ ]本
使った型: [ ]
反応(保存・リプライ・引用)の傾向: [ここに気づいたことを書く]
困っていること: [ここに書く]

用語集

用語 意味
保存(ブックマーク) 投稿を後で見返すために保存する行動。評価が高いとされる指標
引用リポスト コメントを添えて他人の投稿を再投稿すること
リプライ75x 投稿者自身がリプライに返信すると、いいねより大きく評価されるとされる仕組みの通称
CTA 読者に取ってほしい行動を促す一言(保存して・リプで教えて、など)
