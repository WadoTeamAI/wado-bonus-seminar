フック設計 プレイブック＋Hook Skill

最初の1行で、読むか読まないかの9割が決まります。この特典は、その1行を「なんとなく」ではなく型で作れるようにするための資料です。心理フック12種の使い方と、AIに繰り返し作らせるための指示書(SKILL.md)をそのまま渡します。

はじめに

わどです。この特典は、あなたが書くX投稿・note記事・LINE配信・セミナー冒頭の「最初の1行」を強くするためのものです。

どれだけ中身が良くても、最初の1行で止まらなければ最後まで読まれません。逆に、内容が平凡でも最初の1行が正しく作られていれば、そこで止まって続きを読んでもらえます。フックは「うまい言い回し」ではなく、人間の脳がどう反応するかを踏まえた「装置」です。この装置の作り方を、型として持ち帰ってください。

このページには、心理フック12種の一覧と、AI(ChatGPT・Gemini・Claudeのどれでも)に投げれば毎回同じ品質でフック案を10個出させるための指示書を両方載せています。Claude Codeを使っている方には、Skill(手順書)としてそのまま設置できる形も用意しました。

この特典の進め方

上から順に読んでください。最初のゴールを終えたら、「2 心理フック12種」を通し読みし、自分がよく使う媒体(X・note・LINE・セミナーなど)の型を3つだけ選びます。全部を覚える必要はありません。3つ使いこなせれば、今日から発信の反応が変わります。

最初のゴール(今日やる1つ)

今日のゴールは1つだけです。

今書きかけの投稿・記事の最初の1行を、この特典の「2 心理フック12種」から1つ選んで書き直す。

書き直したら、「6 フックの検算」の5項目に当ててみてください。それだけで、今日1本分の反応は変わります。

1. フックとは何か(最初の1行の役割)

フックとは、読者が「続きを読むか、スクロールして離れるか」を決める最初の接触点です。X なら1行目、note・ブログならタイトルと冒頭3行、LINEなら通知に出る最初の20文字、セミナーなら開始直後の30秒がこれにあたります。

フックの役割は「全部を伝えること」ではありません。むしろ逆で、「これは自分に関係がある」と一瞬で思わせて、続きへの入り口を開けることだけです。情報を全部詰め込んだフックは、処理に時間がかかるぶん読み飛ばされます。

フックが動かす脳の反応は、だいたい次の5つのどれかです。

# 反応 何が起きるか
1 好奇心ギャップ 「知らないことがある」と気づき、埋めたくなる
2 損失回避 「これを逃すと損をするかも」と身構える
3 未完了感 話の続きが気になって離れられない
4 社会的証明 「みんなやっている」を見て自分ごと化する
5 処理のしやすさ 短く具体的な言葉ほど「本当らしい」と感じる

型を選ぶ前に、まず「この5つのうちどれを起こしたいか」を1つ決めてください。ここを決めずに書き始めると、あれもこれも詰め込んだ弱いフックになります。

2. 心理フック12種

各型に、型の説明・架空の例文2本・使いどころ・やりすぎの兆候をまとめました。例文はすべて説明用に作った架空のものです。数字や成果はそのまま使わず、必ずあなた自身の事実に置き換えてください。

型1: ベネフィット先出し型

読者が得られる結果を、理由を予告しながら先に言い切る型です。

  • 例文A:「AIに任せる作業を1つ減らすだけで、週の作業時間が短くなります。理由は『判断』を人が持ったままにするからです」
  • 例文B:「投稿の反応が変わるのは、書き方より『最初の1行』です」
  • 使いどころ: 読者がまだ課題に気づいていない、認知の入り口
  • やりすぎの兆候: 「〜できます」を連発すると広告っぽくなり信用が落ちる

型2: 痛み→回避型

よくある失敗を指摘し、その原因に触れる型です。

  • 例文A:「投稿が伸びないのは内容のせいじゃありません。最初の1行で説明しすぎているせいです」
  • 例文B:「フォルダに情報を貼るだけでAIの精度が下がる。原因は『整理』を飛ばしているからです」
  • 使いどころ: 読者が「うまくいっていない」と自覚しているとき
  • やりすぎの兆候: 恐怖をあおる言葉が続くと、事実ではなく煽りに見える

型3: 好奇心ギャップ型

問いを立てて、答えをすぐに言わない型です。

  • 例文A:「読まれる文章に共通する『たった1語』があります。理由は最後で説明します」
  • 例文B:「AIに同じ指示をしても結果が変わる。差が出るのは、実は準備の段階です」
  • 使いどころ: 続きまで読ませたい記事の冒頭、動画の最初の数秒
  • やりすぎの兆候: 本文で答えを明かさないと「釣り」になり信頼を失う

型4: 逆張り型

常識とされていることをいったん否定し、理由を短く添える型です。

  • 例文A:「丁寧に説明するほど、実は読まれなくなります」
  • 例文B:「フックは『煽る』ほど弱くなります。強いのは約束と回収です」
  • 使いどころ: 読者がすでに「常識」を信じているテーマ
  • やりすぎの兆候: 否定だけで終わり理由を説明しないと反発を招く

型5: 数字具体化型

時間・回数・手順の数など、具体的な数字で示す型です。

  • 例文A:「フックの型は12種類。今日使うのはそのうち3つだけで十分です」
  • 例文B:「最初の1行を直すのに必要なのは、5分だけです」
  • 使いどころ: 抽象的な説明より「本当らしさ」を出したいとき
  • やりすぎの兆候: 根拠のない数字を使うと、後から信用を失う

型6: 証拠・事例型

架空または匿名化した事例で、やったことを短く示す型です。

  • 例文A:「ある発信者は、投稿の中身を変えずに冒頭の1行だけ変えて反応が増えました」
  • 例文B:「同じ内容でも、書き出しを変えただけで最後まで読まれる割合が上がった例があります」
  • 使いどころ: 「本当にできるのか」という疑いを持たれているとき
  • やりすぎの兆候: 実在しない実績を実話のように語ると誠実さを損ないます。事例は必ず一般化・匿名化してください

型7: 参加型(質問・診断)

読者に問いを投げ、自分ごととして考えさせる型です。

  • 例文A:「あなたの投稿の最初の1行、何を約束していますか?」
  • 例文B:「今書いている文章は『得』と『損回避』、どちらから始まっていますか?」
  • 使いどころ: 読者に立ち止まって考えてほしいとき
  • やりすぎの兆候: 「いいねして」「コメントして」のような行動の強要は反応が下がる

型8: 期限・希少型

期限や制約を、理由とセットで伝える型です。

  • 例文A:「この案内はここまでです。理由は配信の設計上、この形でしか出せないからです」
  • 例文B:「席には物理的な上限があります。埋まり次第、案内を止めます」
  • 使いどころ: 実際に制約がある告知・締切のある案内
  • やりすぎの兆候: 根拠のない「今だけ」「限定」は不当な表示になり得るため、事実のある制約だけを書いてください

型9: 損失回避ワード型

「損」「失った」といった、損失を連想させる言葉を1つだけ置く型です。

  • 例文A:「その1時間、実はやり直しに使われています」
  • 例文B:「投稿を消す前に、原因を1つだけ確認してください」
  • 使いどころ: 読者がすでに何かを失っている・失いかけている状況
  • やりすぎの兆候: 強い言葉を1文に複数入れると煽りに見える。1つだけに絞り、本文で必ず事実として回収する

型10: 変化強調型(ビフォーアフター)

「普通」から「変化後」への差を、数字や状態の対比で見せる型です。

  • 例文A:「毎回30分かかっていた作業が、順番を変えただけで5分になりました」
  • 例文B:「反応がなかった投稿が、冒頭1行の変更だけで最後まで読まれるようになりました」
  • 使いどころ: 手順や仕組みの効果を伝えたいとき
  • やりすぎの兆候: 変化の幅を誇張すると「嘘くさい」と感じられる。裏付け(手順・理由)を本文で必ず示す

型11: 秘密・限定共有型

「あまり言われていないこと」を教える、という形の型です。

  • 例文A:「フックがうまい人ほど、実は型を1つしか使っていません」
  • 例文B:「反応がいい投稿に共通する順番、あまり話されていません」
  • 使いどころ: 読者に「知らなかった」という発見の喜びを提供したいとき
  • やりすぎの兆候: 「秘密」と言っておいて本文で明かさないのは信頼を壊す最悪のパターン。匂わせたら必ず開示する

型12: 否定選別型

「向いていない人」を先に示し、対象を絞ることで残った読者の関与を高める型です。

  • 例文A:「今すぐ結果だけ欲しい人には向きません。仕組みを1つずつ整える人向けの話です」
  • 例文B:「テンプレをそのまま使いたいだけの人には合いません。自分の言葉に直す前提の話をします」
  • 使いどころ: 読者の質を絞りたい、コミュニティや講座の案内
  • やりすぎの兆候: 否定のあとに救済(その人に向けた価値)を書かないと、ただの排他になる

3. 媒体別の使い分け

同じ型でも、媒体によって「勝負する場所」と長さが変わります。

媒体 勝負する場所 目安の長さ 相性の良い型
X短文 1〜2行目 全角40〜70字程度 逆張り型・数字具体化型・痛み→回避型・参加型
X長文(記事) タイトル＋冒頭3行 タイトル30字＋冒頭3行 変化強調型・秘密限定共有型
note タイトル＋冒頭 タイトル30〜40字 数字具体化型・逆張り型・好奇心ギャップ型
LINE 通知プレビュー1行目 20字程度 ベネフィット先出し型・参加型・期限希少型
セミナー冒頭 開始直後30秒 口頭で30秒 ベネフィット先出し型・証拠事例型・好奇心ギャップ型

使い分けの考え方はシンプルです。文字数が短い媒体ほど、型は1つに絞る。X短文で2つ以上の型を混ぜると、1行目が長くなり読まれる前に離脱されます。noteやセミナーのように文字数・時間に余裕がある媒体では、冒頭で型を1つ立てたあと、続く数文で理由を補強する形にします。

どの媒体でも共通する原則が1つあります。フックで約束したことは、本文の中で必ず回収する。回収しない好奇心ギャップや、開示しない秘密は、一度は反応を集めても信頼を落とします。

4. Hook Skill(Claude Code用)

Claude Codeを使っている方向けに、フック生成を毎回同じ手順で回せる指示書(Skill)を用意しました。以下のファイルをそのまま保存すると、/hook という呼び出しでフック案を作れるようになります。

置き場所: ~/.claude/skills/hook/SKILL.md

---
name: hook
description: トピック×媒体に対して12種の心理フック型でタイトル・見出し・冒頭文の案を10個生成し、自己評価とA/B案を提示する。壁打ち・タイトル決め・フック比較に使う。
version: "1.0.0"
---

# フック生成(壁打ち・比較用)

「最初の1行で読むか読まないかが決まる」——すべてのコンテンツの生死はフックで決まる。
このスキルは感覚ではなく、心理メカニズムと型の組み合わせでフックを設計する。

## トリガー

- `/hook [トピック] [媒体]`
- 「フック作って」「フック案出して」「タイトル案出して」「見出し考えて」

## 入力

- トピック: 必須。フックを作る対象テーマ
- 媒体: 必須。X短文 / X長文 / note / LINE / セミナー冒頭 / 動画 / メール件名
- ターゲット: 任意。誰に向けたフックか(未指定なら汎用)
- 型の指定: 任意。12種のうち指定があれば従う。なければ自動選択
- 証拠素材: 任意。実績・事例・データ(架空可。ただし実在するように書かない)

## 心理メカニズム(なぜフックが効くか)

| メカニズム | フックでの使い方 |
|-----------|---------------|
| 好奇心ギャップ | 重要だが未完了の情報を提示し、即答しない |
| 損失回避 | 「避けたい損失」を冒頭に置く |
| 未完了効果 | 結論の一部だけ見せて続きを気にさせる |
| 社会的証明 | 「多くの人がやっている」を事実の範囲で示す |
| 処理流暢性 | 短く・具体的・数字が明確・動詞で動かす |

## 12型フレームワーク

| 型ID | 名称 | 主メカニズム |
|------|------|------------|
| T1 | ベネフィット先出し | 処理流暢性 |
| T2 | 痛み→回避 | 損失回避 |
| T3 | 好奇心ギャップ | 情報ギャップ |
| T4 | 逆張り | 注意喚起 |
| T5 | 数字具体化 | 処理流暢性+具体性 |
| T6 | 証拠・事例 | 社会的証明 |
| T7 | 参加型(質問・診断) | 自己関与 |
| T8 | 期限・希少 | 損失回避+希少性 |
| T9 | 損失回避ワード | 損失回避 |
| T10 | 変化強調(ビフォーアフター) | 好奇心ギャップ+処理流暢性 |
| T11 | 秘密・限定共有 | 情報の非対称性 |
| T12 | 否定選別 | 自己概念の刺激 |

## ワークフロー

### Step 1: 心理メカニズムの選定
媒体×トピックから、狙うべき心理メカニズムを1〜2個特定する。「なぜこのメカニズムか」を1行で述べる。

### Step 2: 型の選定(T1〜T12)
上のフレームワークから最適な型を最大3つ選定する。各型の選定理由を1行で述べる。

### Step 3: フック案10個の生成
選定した型を使い、フック案を10個生成する。1つの型に偏らず、3型をバランスよく使う。媒体の文字数制約を守る。証拠素材があれば活用する(捏造しない)。

### Step 4: 自己評価
各フック案に以下を付記する。
- 使用型: T1〜T12のどれか
- 狙う心理メカニズム: 1つ
- 期待一致: OK / 要修正(フックの約束を本文で回収できるか)
- 強度: 3段階(強い/中程度/弱い)
- KPI仮説: 1行

### Step 5: A/B案の提示
10個から対照的な2案を選び、A/B案として提示する。A案は最も引きが強いもの、B案は異なる型で比較用。どちらを先にテストすべきか理由とともに推奨する。

## 判断基準

- フックは「驚かせる言葉」ではなく「特定の心理を起動して次の1歩を踏ませる装置」として設計する
- 好奇心ギャップ・秘密を使った場合、本文で必ず回収・開示する。回収しないものは出力しない
- 損失回避ワードは1案に1つまで。複数重ねると煽りに見えるため候補から外す
- 数字・実績は出典があるものだけ使う。出典がない場合は「例」であることを明記する
- 「誰でも」「必ず」「保証」を含む案は自己評価で「要修正」とし、事実ベースの表現に差し替える

## セルフチェック

- [ ] 心理メカニズムが明確か(「なんとなく引きがある」はNG)
- [ ] この1行で読者の手が止まるか
- [ ] 「続きを見ないと落ち着かない」未完了感があるか
- [ ] フックの約束を本文で回収できるか(釣りにしない)
- [ ] 3案以上を異なる型で比較したか
- [ ] 「誰でも」「必ず」「保証」のような断定表現が入っていないか

保存したら、Claude Codeで /hook AIマネタイズの始め方 note のように打つだけで、上の手順が実行されます。

5. 同じことをGem／ChatGPTで回すプロンプト

Claude Codeを使わない方は、以下をそのままGeminiの「Gemを作る」画面の指示欄、またはChatGPTのカスタムGPT(または毎回のプロンプトの先頭)に貼ってください。

あなたは「フック設計アシスタント」です。ユーザーが投げたトピックと媒体に対して、心理フック12種の型を使ってフック案を10個作ります。

# 12種の型
T1 ベネフィット先出し / T2 痛み→回避 / T3 好奇心ギャップ / T4 逆張り /
T5 数字具体化 / T6 証拠・事例 / T7 参加型(質問・診断) / T8 期限・希少 /
T9 損失回避ワード / T10 変化強調(ビフォーアフター) / T11 秘密・限定共有 / T12 否定選別

# 手順
1. ユーザーからトピックと媒体(X短文/X長文/note/LINE/セミナー冒頭/動画/メール件名)を受け取る。片方が無ければ質問して確認する
2. 媒体の文字数・時間の制約を踏まえ、相性の良い型を最大3つ選び、選定理由を1行ずつ述べる
3. 選んだ型を使い、フック案を10個作る。1つの型に偏らせない
4. 各案に「使用型」「狙う心理メカニズム」「期待一致(OK/要修正)」「強度(強い/中/弱い)」を付ける
5. 10個の中から対照的な2案をA案・B案として提示し、先にテストすべき方を理由付きで推奨する

# 出力形式
- 型選定の理由(3行以内)
- フック案10個の表(番号/フック文/型/メカニズム/強度)
- A/B案とテスト推奨

# 禁止事項
- 「誰でも」「必ず」「保証」など断定的な成果の約束をしない
- 実在しない実績・数字を事実のように書かない(架空の例なら「例えば」と明記する)
- 好奇心ギャップ・秘密を使った案は、本文側で回収できることが前提。回収できない案は候補から外す
- 恐怖をあおる表現、過度な限定・煽りは使わない
- 出力は日本語で、丁寧すぎない自然な文体にする

このシステム指示を貼ったあとは、「トピック:AIで作業時間を減らす方法/媒体:note」のように投げるだけで、10案が返ってきます。

6. フックの検算(5チェック)

フック案を1つ書き終えたら、投稿・公開する前に次の5つを確認してください。

  1. どの心理メカニズムを狙っているかを1行で言えるか(「なんとなく」で書いていないか)
  2. 好奇心ギャップ・秘密を使った場合、本文で回収・開示できているか
  3. 損失回避ワードは1つだけか(複数重ねていないか)
  4. 数字や事例を使った場合、出典があるか、架空だと分かる書き方になっているか
  5. 「誰でも」「必ず」「保証」のような断定が混ざっていないか

5つとも「はい」になったら、投稿してかまいません。1つでも「いいえ」があれば、その項目だけ直してから公開してください。

最初に投げるプロンプト

導入直後に、ChatGPT・Gemini・Claudeのどれでもいいので、まず次のプロンプトを1回投げてください。

今から「フック設計 プレイブック」の12種の型を使います。
私のトピックは「{あなたが今伝えたいこと}」、媒体は「{X短文/note/LINE/セミナー冒頭のどれか}」です。
相性の良い型を3つ選んで理由を教えたうえで、フック案を5個作ってください。
各案に、狙っている心理メカニズムを1行で添えてください。

これで、今日書きかけの1本に使える案が返ってきます。

よくある失敗7つと直し方

  1. 型を1つに絞らず全部盛り込む → 型は1文に1つ。複数の型を混ぜると長くなり読まれる前に離脱される
  2. 好奇心ギャップを使って本文で答えを明かさない → 「釣り」として信頼を失う。フックで開けた問いは必ず本文で閉じる
  3. 数字や実績を出典なしで断定的に書く → 「例えば」と明記するか、自分が確認できる事実だけを使う
  4. 損失回避ワードを1文に何個も入れる → 煽りに見える。1つだけに絞り、事実として回収する
  5. 「誰でも」「必ず」を使ってしまう → 断定表現は誤認を招く。「〜という考え方があります」など、事実の範囲に言い換える
  6. 媒体の文字数を無視して長く書く → Xの1行目やLINEの通知は特に短い。まず短くしてから、削れる言葉をさらに削る
  7. 毎回同じ型を使い続ける → 読者が「またこれか」と慣れてしまう。配信が続く場合は、型を意図的にバラす

安全に使うための注意

  • 回収できないフックは出さない: 好奇心ギャップや秘密を匂わせたら、本文で必ず答えを明かす
  • 恐怖をあおらない: 損失回避は「事実としての衝撃」であって、根拠のない不安をあおることではない
  • 実績・事例は誠実に: 架空の例は「例えば」と明記する。実例を使う場合は、本人の許可なく個人が特定できる形にしない
  • 成果の断定を避ける: 「必ず」「誰でも」「保証」といった表現は使わない
  • AIが作った文章であることを隠さない: フックはAIの下書きを人が最終確認したうえで使う。人の目を通さずそのまま公開しない
  • 「いいねして」「コメントして」の強要をしない: 自然な提案(「必要なら保存してください」など)にとどめる

つまずいたときに聞くプロンプト

  • 「このフック案、好奇心ギャップを使っていますが、本文で回収できていますか?」
  • 「このフック、断定的な表現が入っていないか確認してください」
  • 「同じ型ばかり使っていないか、直近5本のフックを型で分類してください」
  • 「このフックを、もっと短く(全角40字以内に)言い換えてください」
  • 「このフックの強度が弱いと感じます。別の型で3案作り直してください」

出す前の品質チェック(10項目)

  1. どの心理メカニズムを狙っているか、1行で説明できるか
  2. フックの約束を本文で回収できているか
  3. 断定表現(「誰でも」「必ず」「保証」)が入っていないか
  4. 数字・実績に出典があるか、架空だと分かる書き方になっているか
  5. 損失回避ワードを1つに絞っているか
  6. 媒体の文字数・秒数の制約を守っているか
  7. 「いいねして」「コメントして」のような行動の強要になっていないか
  8. 事例が実在の個人を特定できる書き方になっていないか
  9. 同じ型を直近の投稿で連続して使っていないか
  10. 声に出して読んだとき、友人に話しても引かれない言い方になっているか

最新AI（2026年9月時点）でこの特典はどう変わるか

この特典では: Hook Skill は Claude Code で動きます。2026年9月時点の Claude Code は Opus が既定で、このスキルはそのまま動きます。

2026年9月の第1週に、主要な AI が続けて更新されました。この特典の手順は変わりませんが、次の3点を知っておくと手数が減ります（2026年9月6日時点の公開情報です。提供状況は変わるので、使う前に各社の公式サイトで確かめてください）。

  • GPT-6 Astra（OpenAI・2026年9月3日発表）: 画面の情報を読み取り、アプリを人間と同じ画面経由で動かす「コンピュータ操作」が主機能になりました。フォーム入力・表計算・資料づくりのような「手順が決まっている作業」を任せやすくなります。ただし段階的な提供の途中で、自分のアカウントにまだ出ていないことがあります。画面に映った文章をそのまま指示として読むことがあるので、AI に画面を触らせるときは「映すものを選ぶ」を守ってください。
  • Claude Fable 5.1（Anthropic・2026年9月1日発表）: 数時間から数日にわたる、複数アプリをまたぐ作業を最小限の監督で回すための最上位モデルです。この特典の作業は Sonnet／Opus で足ります。「何日もかかる仕事を丸ごと任せる」段階になってから検討してください。Claude Code の導入は特典「Claude Code 最初の30分」で扱っています。
  • AI社員: 上の2つが向いている先は同じです。「毎回同じ指示を書かなくていい担当」を1人ずつ増やす形が、個人でも現実になりました。この特典のプロンプトやシステム指示は、そのまま AI社員の「指示書」の1枚になります。つくり方は特典「AI社員1人目のつくり方」で扱っています。

モデルの差で成果は決まりません。何に使うかで決まります。この特典の手順を1周してから、新しいモデルを試してください。
