AI社員1人目のつくり方

役割定義シート・指示書・チェックリストの3枚をひと組みにして、今日中に「毎回同じ指示を書かなくていい」担当を1人つくります。

はじめに

わどです。この特典は、AIを「使う」から「任せる」に切り替えるための、いちばん最初の1歩を作るためのものです。

普段AIを使うとき、多くの人は毎回同じことを書いています。「こういうものを作ってほしい」「トーンはこう」「これはやらないで」。この繰り返しをやめて、1枚の指示書にまとめて持たせる。それが「AI社員」という考え方です。

このページには、役割を決めるシート・指示書(システム指示)・出力を確認するチェックリストの3枚と、それをそのまま埋められるプロンプト、企画1本に必要な5つの制作物を同じ型で作るプロンプト、Claude Codeで動かす場合のスキルファイルまで入っています。今日中に、あなた専用の担当を1人作れる状態にしてあります。

この特典の進め方

上から順に読んで、途中で手を止めずに最後まで進めてください。3枚セットの考え方を先に読んでから埋める作業に入ると迷いません。所要はテストまで含めて90分ほどです。今日は指示書が1枚できていれば十分です。

最初のゴール(今日やる1つ)

今日のゴールは1つです。

「最初に投げるプロンプト」をコピーして投げ、質問に答えて、指示書を1枚作る。

これができれば、あなたの頭の中にしかなかった判断基準が、外に取り出せた状態になります。

1. 「AI社員」とは

使うと任せるの違い

「AIを使っている」状態と「AI社員がいる」状態は、似ているようでまったく違います。

使っている状態は、毎回自分が指示を組み立てています。「こういうものを作ってほしい」「トーンはこう」「これはやらないで」を毎回書いている限り、指示を出す作業そのものが消えません。構造としては外注と同じです。手は借りられても、判断のコストは自分に残ったままです。

任せている状態は、判断基準を一度渡してあります。担当は、書かれていない場面でも「この場合はこちらを優先する」と自分で決めて動けます。しかもこの担当は疲れません。基準もブレません。深夜でも品質が同じです。人に頼むと、ここが管理のいちばんの負担になります。

手順だけでは足りない理由

指示書を作るとき、多くの人は「まず〇〇を開く」「次に△△を書く」と手順から書きます。ですが手順は「こういう場合はこうする」の集まりでしかありません。書いていない場合が来たら対応できませんし、現実の作業では書いていない場合がふつうに来ます。元の材料が想定より少ない、指定の文字数に収まらない、2つの条件が両立しない、前提が変わった、といった具合です。

手順だけを渡された担当は、止まるか、勝手に判断して外すかのどちらかです。判断基準を渡しておけば、担当は自分で優先順位を決めて、外さない答えを返してきます。これが「1人任せられる」の中身です。

2. 3枚セットで、最初の1人を作る

最初の1人には、次の3枚を用意します。役割定義シートで「何を渡すか」を決め、指示書で「どう動くか」を決め、チェックリストで「合格かどうか」を確認します。

役割定義シート

1人作るたびに、先にこの項目を決めます。埋めずに作ると、あとで必ず戻ってきます。

■ 役割の名前：
■ この担当がやること：
■ この担当がやらないこと：
■ 渡す材料(何を渡せば動けるか)：
■ 合格ライン(数えられる形で3つ)：
　1.
　2.
　3.
■ 週にかかっている時間：　　時間
■ 渡したら浮く想定：　　時間

最初の1人には「下書き係(配信文・告知文)」がよく選ばれます。やること＝公式LINEの配信文・告知の下書きを書く、やらないこと＝配信の予約設定・実績や数字の追加・価格に関する記述、合格ラインは「文字数以内」「1行目で続きを読みたくなる」「誘導が1つだけ」の3つ、というふうに埋めます。次の指示書の記入例も、この担当で揃えてあります。

指示書(システム指示)

役割定義シートが決まったら、指示書に落とします。そのまま埋められる形にしてあります。

【担当する範囲】
やること：
やらないこと：

【守るべき判断基準】※優先順位の高い順に5つ
1.
2.
3.
4.
5.

【迷ったときのルール】※3つ
・　　　と　　　がぶつかったら、　　　を優先する
・情報が足りないときは、　　　する
・基準どうしがぶつかったときは、　　　を優先する

【作業の手順】
1.
2.
3.

【完成の合格ライン】※3つ・数えられる形で
・
・
・

【やってはいけないこと】※3つ・理由つきで
・(　　　)なぜなら(　　　)
・(　　　)なぜなら(　　　)
・(　　　)なぜなら(　　　)

【自分に確認を取るべきケース】※2つ
・

結果が変わるのは3項目です。「迷ったときのルール」には必ず「情報が足りないときは想像で埋めずに、不明と書いて止める」を入れてください。これがないと、それっぽい嘘が自然な文章に混ざり、数字や固有名詞の間違いで一度に信頼を失います。「やってはいけないこと」は理由をセットで書くこと。理由があると、書いていない場面でも判断できます。「自分に確認を取るべきケース」は、危ないところだけを先に決める項目です。ここが決まると、残りは全部任せられます。

記入例(下書き係)

【担当する範囲】
やること：公式LINEの配信文を書く
やらないこと：配信の予約設定、画像の作成、実績・数字の追加

【守るべき判断基準】
1. 本文は400字以内。500字を絶対に超えない
2. 1行目だけで開きたくなる形にする
3. 絵文字は3個以上5個以内。同じものを2回使わない
4. 最後は1つの行動だけを促す
5. URLの直後に括弧や記号を付けない

【迷ったときのルール】
・文字数と情報量がぶつかったら、文字数を優先する
・削るときは、具体例ではなく説明のほうから削る
・情報が足りないときは想像で埋めず「ここが不明」と書いて止める

【完成の合格ライン】
・400字以内に収まっている
・1行目が25字以内
・誘導が1つだけ

【やってはいけないこと】
・煽りだけで中身のない文にすること(なぜなら信頼を失うから)
・「詳しくはこちら」だけで中身を伝えないこと(なぜなら開かれないから)
・本文に書いていない内容を1行目に書くこと(なぜなら期待とズレるから)

【自分に確認を取るべきケース】
・数字や実績に触れるとき
・価格に触れる内容が出てきたとき

チェックリスト

指示書ができても、出てきたものをそのまま出さないでください。渡す前に、この形で確認します。

【出力チェックリスト】
- [ ] 合格ラインを全て満たしているか(数字で確認する)
- [ ] やってはいけないことに触れていないか
- [ ] 数字・固有名詞を想像で埋めた箇所がないか
- [ ] 自分の言葉のトーンに合っているか(AIっぽい言い回しが残っていないか)
- [ ] 確認が必要なケースに該当する内容が含まれていないか
- [ ] 読み返して、そのまま出して恥ずかしくないか

3枚がそろったら、指示書は保存しておいてください。次からは「いつもの配信文お願い」で通ります。プロンプトを毎回貼る作業自体が、渡せる作業だということです。

3. 5点セット量産プロンプト

企画を1本出すには、だいたいLP・スライド・配信文・教材・告知の5つの制作物が要ります。ここでは、その5つを同じ考え方で作れるプロンプトの型を紹介します。

使う前に、3つだけ埋める

どのプロンプトも、この3つが埋まっていないと精度が出ません。

【変数1】誰に向けるか
　悪い例：AIに興味がある人
　良い例：AIで副業を始めたいが何から手をつけていいか分からない、
　　　　　本業がある30代の会社員。月◯万円の副収入が目標

【変数2】何を届けるか
　悪い例：AI活用講座
　良い例：AIで教材を作って売るまでの手順を、◯週間で身につける講座。
　　　　　週◯時間の作業で、最終週に1本目を販売開始できる状態にする

【変数3】どのトーンで書くか
　悪い例：親しみやすく
　良い例：友達に説明するような話し言葉。専門用語は使わない。
　　　　　1文40字以内。断定して言い切る。二人称は使わない

「誰に」を1行で済ませると、誰にでも当てはまる文章が返ってきます。誰にでも当てはまる文章は、誰にも刺さりません。変数1と2は、それぞれ50字以上書いてください。それだけで出力が変わります。

型その1 公式LINE配信文

公式LINEの配信文を書いてください。

【誰に】
【何を】
【トーン】
【この配信の目的】(例：セミナーの申し込みを促す)

条件：
・本文は400字を目標にすること。どんな場合でも500字を超えないこと
・書き終わったら実際の文字数を数えて報告すること
・1文は40字以内
・1行目は通知欄に出るので、そこだけで開きたくなる形にすること
・1行目は全角25字以内
・絵文字は3個以上5個以内。同じ絵文字を2回使わないこと
・URLを入れる場合、URLの直後に括弧や記号を付けないこと
・最後は1つの行動だけを促すこと。複数の誘導を混ぜないこと
・改行は3行以上続けないこと

出力の形：
【通知欄フック】(1行・全角25字以内)
---
(本文)
---
文字数：　字
絵文字の数：　個
誘導の数：　個

文字数が500字を超えた場合、その場で削った版を出すこと。
削るときは、具体例ではなく説明のほうから削ること。

禁止事項：
・「詳しくはこちら」だけで中身を伝えないこと
・煽りだけで中身のない文にしないこと

残り4つ(LP・スライド・教材・告知)も、同じ型で作れます

上の公式LINEプロンプトを1つ覚えれば、残り4つも同じ考え方で回せます。

  • LP: まず構成案を表で出させる(ブロック数・目的・目安の文字数)。次に見出しを型別に数で出させる(疑問型・数字型・思い込みを壊す型など)。最後にブロックごとの本文を書かせ、文字数と具体例の数を自己チェックさせる
  • スライド: まず章立てを表で出させる(章・時間配分・扱う内容)。次に1枚ごとの中身を割らせる(見出し・要素・話す要点)。最後に話す原稿を書かせ、時間との差を報告させる
  • 教材: まず目次を表で出させる(章・節・できるようになること)。次に節ごとの本文を書かせる(具体例・そのまま使える形・課題を必ず1つ)。最後に章ごとの課題を作らせる(所要時間・チェック項目つき)
  • 告知の投稿: まず1文目だけを型別(数字を出す型・思い込みを壊す型・場面が浮かぶ型・疑問を投げる型・言い切る型)に数で出させる。1文目が弱いと本文がどれだけ良くても読まれないので、ここだけ先に固める。次に選んだ1文目に続けて本文を書かせる

どの制作物も、1. 表や数出しで全体設計を出させる、2. パーツを型で分けて出させる、3. 本文を書かせて自己チェックさせる、の3段階です。「保証や断定のしすぎになる表現を使わない」「根拠のない数字は[数字]のように残す」の2条件は、5つすべてに共通で付けてください。ここまでできると、出す指示は自分ですが、形にする作業はほぼ渡せます。出てきたものは、確認せずにそのまま出さないでください(確認の仕方は「安全に使うための注意」にまとめました)。

4. 30の役割から「最初の1人」を選ぶ

企画を1本回すのに必要な役割を数えると、リサーチ・構成・コピー・スライド・図解・配信文・告知・教材の整形・サポート返信・数字の集計で10個です。前半用と後半用のように性質が違う工程まで分けると、必要な役割はさらに増えます。

ただし、いきなり全部は要りません。最初の1人は、次の2つが重なるものから選んでください。

  1. 時間を食っている(週にかかる時間が長い)
  2. 判断が要らない(型が決まっている・ルールが決めやすい)

この2つが重なりやすいのは、配信文の下書き・告知の下書き・教材の下書きの3つです。逆に、企画の方向性そのものを決める役割や、価格に関わる判断は渡さないでください。ここは自分の頭でやる部分です。「案を出させて選ぶ」形までなら使えます。

増やすときに気をつけること

1人目がうまく回ったら、2人目・3人目と増やしていきます。ここで、実際に手を動かした人だけがぶつかる問題が3つあります。

  • 担当どうしがぶつかる: 後工程の担当が、前工程の判断を勝手に変えることがあります。「やらないこと」に前工程の領域をはっきり書いておきます
  • 同じ材料を何度も渡すことになる: お客さんの像・トーン・禁止事項を、担当が増えるたびに毎回貼ることになります。共通の基準を1枚にまとめ、各担当の冒頭でそこを見る形にしておきます
  • 増やしたのに時間が減らない: 作って満足して使わない担当が生まれます。月に1回、「今月1回も呼ばなかった担当」を数えてください。3人以上いたら作りすぎです

5. Claude Codeで動かす場合

Claude Codeを使っている場合は、指示書とチェックリストを1つのスキルにまとめて持たせられます。置き場は次のパスです。

~/.claude/skills/ai-employee-01/SKILL.md

以下がSKILL.mdの全文です。役割定義シートで決めた内容を、{{ }}の部分に差し替えて使ってください。

---
name: ai-employee-01
description: 役割定義シートで決めた1つの担当(下書き・下読み・集計など)の作業を、指示書の判断基準に沿って実行し、出力前にチェックリストで確認するスキル。「{{担当名}}お願い」で発動する。
version: "1.0.0"
---

# ai-employee-01

役割定義シート1枚分の担当を代行するスキル。担当する範囲は{{担当する範囲}}、担当しない範囲は{{やらないこと}}。

## トリガー
- 「{{担当名}}お願い」「{{担当名}}の下書き作って」

## 入力
- 対象の材料(元原稿・誰に向けるか・トーン)
- 過去の完成品(あれば。トーンの参照にする)

## ワークフロー

### Step 1: 材料の確認
- 誰に向けるか・何を届けるか・トーンの3点が揃っているか確認する
- 1つでも欠けていたら、書き始めずに質問して止まる

**判断基準**: 「誰に」「何を」が抽象的(1行未満)な場合は、具体化する質問を1つ追加してから進める。

### Step 2: 判断基準に沿って作成する
- 指示書の【守るべき判断基準】を優先順位順に適用する
- 判断基準どうしがぶつかる場合は【迷ったときのルール】に従う
- 情報が足りない箇所は、想像で埋めず「ここが不明」と書いて止める

**判断基準**: 【やってはいけないこと】に該当する内容が混ざっていないか、生成の都度自分で確認する。

### Step 3: 出力前チェック
- 【完成の合格ライン】を1つずつ数字で確認し、満たしていない項目があれば自分で直す
- 【自分に確認を取るべきケース】に該当する内容(数字・実績・価格など)が含まれる場合は、書かずに確認を求める

**判断基準**: 合格ラインは「満たした/満たしていない」で判定できる形にする。「たぶん大丈夫」で通さない。

### Step 4: 報告
- 完成品と一緒に、チェックリストの結果を箇条書きで報告する
- 想定外の状況(材料が普段と違う・条件が両立しない)に当たった場合は、その旨を添えて報告する

## 禁止事項
- ユーザーが渡していない実績・数字・固有名詞を作らない
- 【やらないこと】に書かれた範囲に手を出さない
- 合格ラインを満たさないまま「完成」と報告しない

## セルフチェック
1. 【守るべき判断基準】を優先順位どおりに適用したか
2. 想像で埋めた数字・固有名詞がないか
3. 【完成の合格ライン】を数字で確認したか
4. 【自分に確認を取るべきケース】に該当する内容を、確認なしに出していないか

6. 1週間の試用の回し方

1人目は、作って終わりにしないでください。1週間、実際の作業で使ってみて、ズレを直していきます。

  • 1日目: 指示書を作り、テストする(いつもの仕事を投げる/想定外を投げる/やってはいけないことを踏ませる)
  • 2〜3日目: 実際の作業で使う。出てきたものをチェックリストで確認し、直した箇所を控えておく
  • 4〜5日目: 控えた直し方をもとに、指示書の【守るべき判断基準】か【迷ったときのルール】に1行足す
  • 6日目: 再テストする。同じ想定外を投げて、直った分だけ良くなっているか確認する
  • 7日目: 週の作業時間を振り返り、実際にどれだけ浮いたかを数字で見る

1回で完璧な指示書はできません。使いながらズレたところを1行ずつ足していく回数が、そのまま精度になります。週に1回、次のプロンプトを投げると振り返りが早いです。

これまでのやりとりを振り返って、この指示書に足りない基準を3つ挙げてください。

条件：
・実際にズレが出た箇所を根拠にすること
・根拠がない推測での提案はしないこと
・3つちょうど挙げること
・それぞれ、指示書のどの項目に追記すべきかも書くこと

最初に投げるプロンプト

自分で埋めるのがしんどい場合は、こちらを使ってください。質問に答えるだけで指示書が埋まります。ChatGPT・Gemini・Claudeのどれに投げても構いません。

あなたは業務の引き継ぎ設計の担当です。
これから、ある作業を任せるための指示書を作ります。

私がいちばん時間を取られている作業はこれです：
【ここに、渡したい作業を書く】

【手順1】
いきなり指示書を書かないでください。
まず、この作業について私に質問を8個してください。

質問の条件：
・私が無意識に使っている判断基準を引き出す質問にすること
・「どうやっているか」ではなく「なぜそうしているか」を聞くこと
・以下を必ず1問ずつ含めること
　- 過去にやり直しになったのはどんなときか
　- 人に頼んだとして、いちばん心配なのは何か
　- 出来上がりを見て「違う」と感じるのはどういう場合か
・1問ずつ順番に聞くこと。まとめて8問出さないこと

【手順2】
私の回答が出そろったら、以下の項目を埋めた指示書を作ってください。

・担当する範囲(やること／やらないこと)
・守るべき判断基準を5つ(優先順位つき)
・迷ったときに何を優先するかのルールを3つ
・作業の手順を番号付きで(5工程以内)
・完成の合格ラインを3つ
・やってはいけないことを3つ(それぞれ理由つき)
・自分に確認を取るべきケースを2つ

各項目の条件：
・判断基準は5つちょうどにすること。6つ以上に増やさないこと
・合格ラインは「数字」か「あるかないか」で判定できる形だけにすること
　(「読みやすい」「いい感じ」のような主観判定は使わない)
・「迷ったときのルール」には、必ず
　「情報が足りないときは想像で埋めずに、不明と書いて止める」を含めること
・やってはいけないことには、必ず理由を添えること
・手順は5工程以内にまとめること。多い場合は担当を分けることを提案すること

【手順3】
指示書を出したあと、以下を報告してください。
・この指示書で対応できない場面を3つ挙げること
・そのうち、いま追記すべきものと、使いながら足せばいいものに分けること

禁止事項：
・手順1を飛ばして指示書を書かないこと
・手順3で「特にありません」と答えないこと。必ず3つ挙げること
・私の回答をそのまま並べただけの指示書にしないこと。
　回答の裏にある基準を言語化すること

進行のルール：
・手順1の質問が終わったら「手順2に進みます」と宣言してから続けること
・手順2以降は、私の指示を待たずに手順3まで一気に進めること
・各手順の冒頭に手順番号を書くこと

いきなり書かせないのが要点です。質問を挟むと、自分の頭の中にある基準が引き出されます。手順3の「対応できない場面を3つ挙げさせる」も効きます。作ったものの穴を自分で探させると、抜けが見つかります。

よくある失敗 7つと直し方

1. 指示書が長すぎる

全部を書こうとすると、逆に精度が落ちます。判断基準は5つまで。10個渡された担当は優先順位をつけられません。長くなった場合は使う頻度が低い項目から削ってください。困ったら足せばいいだけです。

2. 合格ラインが感覚のまま

「読みやすく」「いい感じに」は判定できません。数字か「あるかないか」で書けたものだけが、実際に渡せる作業です。数字にすると、担当は自分で確認して直せるようになります。

3. 1回作って終わりにする

1回で完璧な指示書はできません。使いながらズレたところを1行ずつ足していきます。週に1回の振り返りが早いです(6章の週次プロンプトを使ってください)。

4. いきなり難しい作業から渡す

1人目は「型が決まっているもの」から始めてください。難しい作業から始めて失敗すると、「やっぱり任せるのは無理だ」と結論を出してしまいます。渡しやすさが高いものから選びます。

5. 担当どうしがぶつかる

後工程の担当が、前工程の判断を勝手に変えることがあります。「やらないこと」に前工程の領域を明記してください。

6. 同じ材料を何度も渡すことになる

担当が増えると、お客さんの像・トーン・禁止事項を毎回貼ることになります。共通の基準を1枚にまとめておき、各担当の冒頭で参照する形にします。

7. 増やしたのに時間が減らない

作って満足して使わない担当が出てきます。月に1回、「今月1回も呼ばなかった担当」を数えてください。3人以上いたら作りすぎのサインです。

安全に使うための注意

  • 実績・お客様の声・数字は、実在するものだけを書かせてください。根拠のない数字は「[ここに自分の数字を入れる]」のように残す指示を必ず入れます
  • 「必ず」「絶対」「誰でも」「保証」「100%」「確実に」といった言い切り表現は、出力に混ざっていないか毎回確認してください
  • 価格・お客様の個人情報・機微な情報に触れる出力は、【自分に確認を取るべきケース】に必ず含めてください
  • 出てきたものをそのまま出さないでください。数字と固有名詞は目で確認する工程を、必ず自分の作業に残してください
  • 指示書やチェックリストに、実在の第三者の名前や連絡先を書き込まないでください

つまずいたときに聞くプロンプト

いま作った指示書を見て、私が想定していない使い方をされそうな場面を3つ挙げてください。
それぞれについて、指示書のどこに1行足せば防げるかも書いてください。

この担当に、絶対に確認なしで進めてほしくない場面を洗い出したいです。
私の【自分に確認を取るべきケース】の記述が甘いところを指摘してください。

最新AI（2026年9月時点）でこの特典はどう変わるか

この特典では: 役割定義シート・指示書・チェックリストの3枚は、コンピュータ操作型の AI にもそのまま渡せます。1人目の担当に「画面を触る作業」を割り当てるときは、映すものを選ぶ注意を指示書に足してください。

2026年9月の第1週に、主要な AI が続けて更新されました。この特典の手順は変わりませんが、次の3点を知っておくと手数が減ります（2026年9月6日時点の公開情報です。提供状況は変わるので、使う前に各社の公式サイトで確かめてください）。

  • GPT-6 Astra（OpenAI・2026年9月3日発表）: 画面の情報を読み取り、アプリを人間と同じ画面経由で動かす「コンピュータ操作」が主機能になりました。フォーム入力・表計算・資料づくりのような「手順が決まっている作業」を任せやすくなります。ただし段階的な提供の途中で、自分のアカウントにまだ出ていないことがあります。画面に映った文章をそのまま指示として読むことがあるので、AI に画面を触らせるときは「映すものを選ぶ」を守ってください。
  • Claude Fable 5.1（Anthropic・2026年9月1日発表）: 数時間から数日にわたる、複数アプリをまたぐ作業を最小限の監督で回すための最上位モデルです。この特典の作業は Sonnet／Opus で足ります。「何日もかかる仕事を丸ごと任せる」段階になってから検討してください。Claude Code の導入は特典「Claude Code 最初の30分」で扱っています。
  • AI社員: 上の2つが向いている先は同じです。「毎回同じ指示を書かなくていい担当」を1人ずつ増やす形が、個人でも現実になりました。この特典のプロンプトやシステム指示は、そのまま AI社員の「指示書」の1枚になります。つくり方は特典「AI社員1人目のつくり方」で扱っています。

モデルの差で成果は決まりません。何に使うかで決まります。この特典の手順を1周してから、新しいモデルを試してください。
