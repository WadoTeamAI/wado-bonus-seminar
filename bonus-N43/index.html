STEP1 ヒアリング10問→提案文 Gem

相手から聞いた答えを貼るだけで、提案文の下書きと見積の骨組みが出てきます。金額は自分で入れる欄のまま残るので、相場を知らずに数字を決めてしまう心配はありません。

はじめに

わどです。

STEP1で多くの人が止まるのは、「聞くべきことは分かっているのに、聞いた後どう文章にすればいいか分からない」という段階です。ヒアリングまではできても、そこから提案文に組み立て直す作業に時間がかかりすぎて、1件出す前に力尽きてしまう。よくある流れです。

この特典は、その「聞いた後」の作業を1つのGemに任せるためのものです。相手に聞いた10個の答えを貼ると、あなたの状況に合った提案文の下書きと、見積の項目（金額は空欄のまま）が返ってきます。テンプレートの空欄を自分で埋めるのではなく、対話しながら埋めてもらう形です。

テンプレートを自分の手で埋める形が合う人は、別の特典の穴埋めテンプレートを使ってください。この特典は「相手の言葉をそのまま貼って、対話形式で提案文を組み立てたい」人向けです。どちらが自分に合うかは、実際に両方触ってみて決めて構いません。

この特典の進め方

順番はこの通りです。

  1. 1章のヒアリング10問を読んで、10問すべての狙いを理解する
  2. 2章のシステム指示をコピーする
  3. 3章の作り方の手順でGemを作る（Geminiが使える環境が必要です）
  4. 実際の相手にヒアリング10問を聞き、答えをGemに貼ってみる
  5. 4章の出力例と見比べて、出てきたものの使い方を確認する
  6. Geminiを使っていない、または法人アカウント等でGemが作れない場合は6章の汎用プロンプト版を使う

Gemを作らなくても、6章のプロンプトをそのままAIに貼れば同じことができます。まずはそちらで試してから、繰り返し使うと分かった時点でGem化する、という順番でも問題ありません。

最初のゴール（今日やる1つ）

今日やることは、これだけです。

ヒアリング10問のうち、最初の3問だけでいいので、今検討している相手（または架空の想定相手）への答えを自分の言葉で書き出してみる。

10問全部を一度に埋めようとすると止まります。3問だけ書いてみると、自分がまだ聞けていない項目がどこか、逆算で見えてきます。

1. ヒアリング10問

これから提案する相手、またはすでに話を聞いている相手に、次の10問を確認してください。順番に全部聞く必要はありません。会話の流れに合わせて、聞けるところから聞いてください。

# 聞くこと この問いの狙い
1 何を、いくつ、どんな形式で納品すればよいですか 完成のイメージがずれていると、提案文の方向自体がずれる
2 報酬額はいくらで、そこから引かれる手数料や税はありますか 見積の骨組みを作る前に、相手側の予算感を先に把握するため
3 納期はいつですか。途中で確認のタイミングはありますか 提案文の「進め方」欄に具体的な日付を書けるようにするため
4 誰が、何を見て、いつまでに合否を判断しますか 検収の基準が曖昧なまま提案すると、後で揉める
5 修正は何回まで対応しますか 提案文に「初回確認込みで◯回まで」と自分から書けるようにするため
6 依頼内容が増えた場合、追加費用になりますか、それとも範囲内ですか 見積の項目を「範囲内」と「追加扱い」に分けて書くため
7 途中で契約が終わる場合、それまでの分の報酬はどうなりますか 万一の場合の取り決めを、提案の時点で確認しておく
8 完成品の権利は誰のものになりますか。実績として公開してもよいですか 次の提案文のポートフォリオに使えるかが決まる
9 秘密保持の取り決めはありますか。AIツールを使って作業してよいですか 相手の情報をAIに入力してよいかは、提案前に確認しておく
10 支払いはいつ、どの方法で行われますか 見積の骨組みに支払い条件の欄を作るため

10問すべてに答えがそろっていなくてもGemには貼れます。空欄がある項目は、Gemの側から「まだ聞けていません」として提案文の中で確認事項扱いにしてくれます。

2. Gemのシステム指示 全文

Geminiで「Gemを作る」を選び、指示欄に次の内容をそのまま貼ってください。

あなたは「STEP1提案文ライター」です。個人が受託の仕事に応募・提案するときの、提案文の下書きと見積の骨組みを作る担当です。

■ 役割
利用者がヒアリング10問(納品物、報酬、納期、検収基準、修正回数、追加費用の扱い、途中終了時の扱い、権利、秘密保持、支払い)への相手の回答を貼ってきます。あなたはその回答をもとに、提案文の下書きと見積の骨組みを作ります。

■ 入力
利用者は次の情報を貼ります。
1. ヒアリング10問への相手の回答(全部揃っていない場合もある)
2. 自分の得意分野・経験(あれば実績、なければ「実績なし」と伝えられる)
3. 案件の募集要項や依頼内容の概要

■ 手順
1. 貼られた回答を読み、10問のうちどれが未回答かを先に一覧で示す
2. 利用者の実績の有無を確認し、「実績なし」「小さな実績あり」「紹介経由」の3つの型のうち、どれが今回に合うかを1つ選び、理由を添える
3. 選んだ型で提案文の下書きを書く。募集要項や依頼内容にある言葉をそのまま使い、自分の経歴より先に「できること」を書く
4. 見積の骨組みを表で出す。列は「項目」「工数の目安」「金額」とし、金額欄は必ず空欄のままにする。工数の目安は聞いた回答から推測できる範囲にとどめ、根拠のない数字は書かない
5. 最後に「次のアクション」を3つ以内で出す(未回答の項目を確認する、金額を自分で調べて埋める、送る前に見直す、など)

■ 出力形式
1. 未回答の項目一覧
2. 選んだ型と理由
3. 提案文の下書き
4. 見積の骨組み(表・金額欄は空欄)
5. 次のアクション

■ 禁止事項
- 金額を勝手に埋めない。相場も含めて、必ず利用者自身に調べて入れてもらう
- 「必ず受注できます」「絶対に良い結果になります」のような成果の断定をしない
- 相手の回答の言葉を、意味が変わるほど言い換えない。事実として書かれていないことを提案文に足さない
- 満たせない条件があれば、隠さずそのまま提案文に書く
- 利用者から追加の情報がない限り、実績や経験を作り出さない

3. Gemの作り方

  1. Geminiを開き、左側メニューから「Gemを作成」を選びます
  2. 名前を「STEP1提案文ライター」など、自分が分かる名前にします
  3. 指示欄に、2章のシステム指示をそのまま貼ります
  4. 保存すると、あなた専用のGemとして使えるようになります
  5. 使うときは、そのGemを開いて「ヒアリング10問への相手の回答」と「自分の得意分野」「案件の概要」を貼るだけです

法人アカウントや組織のGoogle Workspaceの設定によっては、Gem作成機能が使えない場合があります。その場合は6章の汎用プロンプト版を、普段使っているAIにそのまま貼って使ってください。

4. 出力例

架空の回答をもとに、実際の出力イメージを示します。数字や固有名詞はすべて架空のものです。

貼った回答(例)

1. 納品物: LP1ページ分のライティング(見出し+本文、Word形式)
2. 報酬: 相手からは未提示
3. 納期: 2週間後
4. 検収: 担当者が確認、基準は特に提示なし
5. 修正: 未確認
6. 追加費用: 未確認
7. 途中終了: 未確認
8. 権利: 未確認
9. 秘密保持: 特になしと聞いている
10. 支払い: 納品月の翌月末

自分の得意分野: Webライティング、実績は自主制作1本のみ

Gemの出力(例)

4(検収基準の詳細)、5(修正回数)、6(追加費用の扱い)、

提案前に、このうち5と8だけでも確認しておくと、提案文の説得力が増します。

■ 選んだ型と理由

自主制作とはいえ完成品が1本あるため、実績なし型より具体的に書けます。

■ 提案文の下書き

はじめまして、△△と申します。

・採用ページの見出し+本文をWord形式で納品いたします
・2週間の納期に対応可能です

■ これまでの実績

■ 今回のご依頼への当てはめ

同じ考え方で構成をご提案できます。

■ 進め方
・着手可能日:【日付】
・修正対応につきましては、回数の目安をすり合わせさせていただけますと幸いです

ご検討のほど、よろしくお願いいたします。

■ 見積の骨組み
| 項目 | 工数の目安 | 金額 |
|---|---|---|
| 構成案作成 | 未回答のため目安なし | |
| 本文執筆(見出し+本文) | 未回答のため目安なし | |
| 修正対応(回数未確定) | 未回答のため目安なし | |

■ 次のアクション
1. 修正回数と権利の扱いを、提案前に相手へ確認する
2. 各項目の金額を自分で調べて表に入れる
3. 提案文を送る前に、募集要項の必須条件と1対1で対応しているか見直す

工数の目安が「未回答のため目安なし」となっている点に注目してください。聞けていない情報から数字を作らないのは、Gemの側の禁止事項として指示に入れてあるためです。

5. 提案文3型の使い分け

Gemが自動で1つを選びますが、自分でも判断できるようにしておくと、Gemの提案に納得しやすくなります。

型 使う場面 特徴
実績なしテンプレ 受注経験がまだない 正直に伝えたうえで、自主制作の成果物を代わりに添える
小さな実績ありテンプレ 自主制作・実案件を問わず、完成品が1件でもある 数字や具体的な工夫点を実績として書く
紹介経由テンプレ 知人や既存クライアントからの紹介がある 紹介元への感謝と、要件への回答を同じ密度で書く

迷ったときは、実績があるかないかで先に2つに絞り、紹介の有無で最後に判断する、という順番で考えると早いです。

6. 汎用プロンプト版

Geminiを使わない、またはGem機能が使えない場合は、次のプロンプトを普段使っているAI(ChatGPT・Gemini・Claudeのどれでも)にそのまま貼って使ってください。中身は2章のシステム指示と同じです。

あなたはこれから「STEP1提案文ライター」として振る舞ってください。

役割: 個人が受託の仕事に応募・提案するときの、提案文の下書きと見積の骨組みを作ります。

これから私が、ヒアリング10問(納品物、報酬、納期、検収基準、修正回数、追加費用の扱い、
途中終了時の扱い、権利、秘密保持、支払い)への相手の回答と、
自分の得意分野・実績の有無、案件の概要を貼ります。

貼ったら、次の手順で進めてください。
1. 10問のうち未回答の項目を先に一覧にする
2. 「実績なし」「小さな実績あり」「紹介経由」の3つの型から1つを選び、理由を添える
3. 選んだ型で提案文の下書きを書く。募集要項や依頼内容の言葉をそのまま使い、
   自分の経歴より先に「できること」を書く
4. 見積の骨組みを表で出す。列は「項目」「工数の目安」「金額」とし、
   金額欄は必ず空欄のままにする。根拠のない工数の数字は書かない
5. 最後に「次のアクション」を3つ以内で出す

禁止事項:
・金額を勝手に埋めない(相場も含めて、必ず私自身が調べて入れます)
・成果を断定しない(「必ず受注できます」等は書かない)
・私が伝えていない実績や経験を作り出さない
・満たせない条件があれば、隠さずそのまま提案文に書く

準備ができたら「回答をどうぞ貼ってください」とだけ返信してください。

最初に投げるプロンプト

Gem、または汎用プロンプト版を用意したら、最初にこれを投げてみてください。

これから、ヒアリング10問への回答を貼ります。
まだ答えが揃っていない項目もありますが、そのまま貼るので、
足りない項目は指摘してください。

1. 納品物:
2. 報酬:
3. 納期:
4. 検収:
5. 修正:
6. 追加費用:
7. 途中終了:
8. 権利:
9. 秘密保持:
10. 支払い:

自分の得意分野・実績:
案件概要:

空欄のまま貼っても構いません。「わからない」「未確認」とそのまま書いて大丈夫です。

よくある失敗 7つと直し方

  1. 10問全部が埋まるまで提案文を作らない → 未回答があってもGemには貼ってよい。埋まっていない項目は「確認事項」として提案文に含めればよい
  2. 金額欄が空欄のままなのを見て、自分で相場を調べずに放置する → 見積の骨組みは骨組みのまま。金額は自分で調べて埋める作業が必ず残る
  3. 出てきた提案文をそのまま送る → 誤字・宛名の残り・自分の状況と合わない箇所がないか、必ず読み返してから送る
  4. 相手の回答の言葉を、Gemが勝手に言い換えていないか確認しない → 出力を読むとき、相手が言っていない内容が足されていないかを毎回チェックする
  5. 工数の目安を、聞いていない項目にまで数字で出してしまう → 「未回答のため目安なし」と出た項目は、そのまま未回答扱いで進める
  6. 1つの型に固執する → Gemが選んだ型に納得できなければ、別の型で出し直してもらってよい
  7. ヒアリングをせずに、想像で回答欄を埋めて貼る → 想像で埋めると、提案文もヒアリングも実態とずれる。分からない項目は「未確認」と書く

安全に使うための注意

  • 金額は必ず自分で確認してから埋める。 相場も含めてAIに丸投げしない
  • 相手の情報をAIに貼ってよいかは、先に確認する。 秘密保持の取り決めがある場合は、貼る前に許可を得る
  • 出てきた提案文をそのまま鵜呑みにしない。 自分の状況と食い違う箇所がないか、必ず自分の目で確認する
  • お金が動く前に作業・納品をしない。 見積の骨組みはあくまで下書きであり、正式な契約条件の確定ではない
  • 困ったときはサービスの窓口に相談する。 契約や支払いのトラブルは、利用しているサービスの運営や公的な相談窓口に相談する。この特典は法律の助言ではない

つまずいたときに聞くプロンプト

  • 未回答の項目が多くて不安なとき: 「未回答の項目のうち、今回の案件で特に確認しておいたほうがよいものを3つ選んで、理由も教えてください」
  • 出てきた提案文が自分の状況と合わないとき: 「今出してもらった提案文のうち、私の実際の状況(下記)と合わない箇所を指摘してください」＋実際の状況を貼る
  • 見積の項目が足りない気がするとき: 「今回の依頼内容(下記)を踏まえて、見積の項目に抜けがないか確認してください。金額は入れなくて構いません」＋依頼内容を貼る
  • 型の選び方に納得できないとき: 「別の型(実績なし／小さな実績あり／紹介経由)で提案文を出し直してください」

用語集

  • ヒアリング: 案件を受ける前に、相手に条件を確認する作業
  • 見積の骨組み: 金額を入れる前の、項目と工数の目安だけを整理した表
  • 提案文の下書き: 送信前提ではなく、そのまま送っても手直ししてもよい途中段階の文章
  • 未回答: ヒアリング10問のうち、まだ相手に確認していない、または相手からの返答がない項目
  • 汎用プロンプト版: Gem機能を使わずに、同じ役割を任意のAIに直接指示する形式

出す前の品質チェック（10項目）

送信ボタンを押す前に、上から順に確認してください。

  1. 未回答だった項目を、送信前に相手へ確認したか
  2. 見積の金額欄を、自分で調べた数字で埋めたか(空欄のまま送っていないか)
  3. 募集要項や依頼内容の必須条件が、提案文の中に全部登場しているか
  4. 自分の経歴より、相手の要求への回答が先に来ているか
  5. 相手の回答の言葉が、意味が変わるほど言い換えられていないか
  6. 満たせない条件を隠さず、正直に書いているか
  7. 誤字脱字、宛名の間違い(コピペの残り)がないか
  8. 着手可能日など、具体的な行動が書かれているか
  9. 見積の工数の目安に、根拠のない数字が入っていないか
  10. 全体を通して、成果を保証するような言い切りをしていないか

最新AI（2026年9月時点）でこの特典はどう変わるか

この特典では: ヒアリングの答えを貼って提案文を出す対話は、そのまま AI社員の「営業アシスタント」の指示書になります。

2026年9月の第1週に、主要な AI が続けて更新されました。この特典の手順は変わりませんが、次の3点を知っておくと手数が減ります（2026年9月6日時点の公開情報です。提供状況は変わるので、使う前に各社の公式サイトで確かめてください）。

  • GPT-6 Astra（OpenAI・2026年9月3日発表）: 画面の情報を読み取り、アプリを人間と同じ画面経由で動かす「コンピュータ操作」が主機能になりました。フォーム入力・表計算・資料づくりのような「手順が決まっている作業」を任せやすくなります。ただし段階的な提供の途中で、自分のアカウントにまだ出ていないことがあります。画面に映った文章をそのまま指示として読むことがあるので、AI に画面を触らせるときは「映すものを選ぶ」を守ってください。
  • Claude Fable 5.1（Anthropic・2026年9月1日発表）: 数時間から数日にわたる、複数アプリをまたぐ作業を最小限の監督で回すための最上位モデルです。この特典の作業は Sonnet／Opus で足ります。「何日もかかる仕事を丸ごと任せる」段階になってから検討してください。Claude Code の導入は特典「Claude Code 最初の30分」で扱っています。
  • AI社員: 上の2つが向いている先は同じです。「毎回同じ指示を書かなくていい担当」を1人ずつ増やす形が、個人でも現実になりました。この特典のプロンプトやシステム指示は、そのまま AI社員の「指示書」の1枚になります。つくり方は特典「AI社員1人目のつくり方」で扱っています。

モデルの差で成果は決まりません。何に使うかで決まります。この特典の手順を1周してから、新しいモデルを試してください。
